1	# Memory borrows — separation discipline for the libc specs
2	
3	Status: design note. Applies to all LowIR libc function specs (hex0, strtoull, …).
4	
5	## The problem
6	
7	LowIR memory is a single flat map `mem : Word → Byte`. The moment a function both
8	mutates memory and reads/writes caller-provided pointers, its postcondition is only
9	true under **non-aliasing** preconditions. Two instances already live in this repo:
10	
11	- **hex0**: reads the input region `[inBase, inBase+len)` and writes the output region
12	  `[outBase, outBase+cap)`. The spec `Hex0.coreSpec` is a pure function of the input
13	  *list*; for the IL to match it, an output write must never perturb an input byte the
14	  parser has not yet read — i.e. input and output regions must be disjoint.
15	- **errno** (conformant `strtoull`, deferred): a global the function writes; must be
16	  disjoint from the caller's buffers, and `strtoull` also writing `*endptr` needs
17	  `endptr ≠ &errno`.
18	
19	## The discipline: Tree-Borrows-style borrows (see `third-party/2025-pldi-treeborrows.pdf`)
20	
21	We phrase each function's memory contract in **borrow** vocabulary:
22	
23	- **shared borrow** (`&[u8]`, e.g. the input `nptr`/`input`): read-only; the bytes are
24	  stable for its lifetime; *may overlap other shared borrows* (two readers of the same
25	  `const char *` is fine).
26	- **unique borrow** (`&mut [u8]`, e.g. the output buffer, or `errno`): exclusive; must be
27	  disjoint from **every** other live borrow (shared or unique).
28	
29	`hex0 : (input : &[u8]) → (out : &mut [u8]) → Status`. From "`out` is unique" the
30	disjointness `Disjoint input out` is a *theorem about borrow well-formedness*, not an
31	ad-hoc hypothesis. `errno` is a libc-held unique borrow, disjoint from caller borrows by
32	the same rule; `sprintf(&errno, …)` is illegal precisely because it would need a second
33	unique borrow overlapping libc's → two overlapping uniques → ill-formed.
34	
35	Tree Borrows (vs Stacked Borrows / raw disjointness) is the right justification because a
36	libc needs: shared borrows that *overlap* (read-read), **dynamic ranges** (a pointer
37	derived from `&arr[0]` may walk the whole slice — what `strtoull` does to `nptr`), and
38	interior pointers. We cite TB as the semantic justification.
39	
40	## Scope: contract residue, NOT the operational model
41	
42	We do **not** port the Tree Borrows operational semantics (per-location permission state
43	machines, the derivation tree, UB triggers — a research-scale effort, and unnecessary:
44	hex0 creates no derived pointers, never reborrows, is single-threaded). We take only the
45	**separation consequence** — a well-formedness predicate and the disjointness it implies:
46	
47	```lean
48	structure Slice where base : Word; len : Nat
49	def Slice.has (s : Slice) (a : Word) : Prop := ∃ k, k < s.len ∧ a = s.base + BitVec.ofNat 64 k
50	inductive Perm | shared | uniq
51	structure Borrow where slice : Slice; perm : Perm
52	def Disjoint (s t : Slice) : Prop := ∀ a, s.has a → t.has a → False
53	def Wf (bs : List Borrow) : Prop :=                 -- a unique borrow is disjoint from all others
54	  ∀ b ∈ bs, ∀ b' ∈ bs, b ≠ b' → (b.perm = .uniq ∨ b'.perm = .uniq) → Disjoint b.slice b'.slice
55	```
56	
57	(currently in `LowIR/CtrlHex0Proof.lean`; promote to `LowIR/Borrow.lean` for libc-wide reuse.)
58

**The design goal**, as the docs state it (DESIGN-THESES thesis 6): fill the empty cell — a borrow-checked, GC-free, C-power language whose proofs carry down to machine code, i.e. *(borrow types) × (verified compilation to bytes)*, with the libc as the driving application.

## Assumptions that can be dropped to reach the goal

Ordered roughly by leverage. Some are constraints the project imposes on itself that the goal doesn't actually require; the last few are TCB items the goal itself makes deletable.

1. **"Compiles with a normal C compiler."** LIBC-FORMALIZE opens with this requirement, and it drives the whole Frama-C Track A, the clean-room-C source posture, and the future C→IL front. But the empty-cell target is explicitly *not C* — it's a new borrow-checked surface. If the deliverable is that language, the libc can be written directly in it and compiled by your own verified backend; C-compilability is a legacy of the doc's earlier framing and dropping it deletes an entire proof track and toolchain dependency. (A C-*ABI-compatible* binary interface can be kept without the source being C.)

2. **POSIX conformance — errno in particular.** The `errno` protocol drags in the single-threaded-TLS assumption (D6), the errno-as-unique-borrow discipline, and the `endptr ≠ &errno` side conditions in MEMORY-BORROWS. For a bootstrap-scale verified libc, errno can simply not exist — return status values (the hex0 `Status` style already does this). POSIX then supplies the spec *shape* only, which is all LIBC-FORMALIZE §2 says it's good for anyway.

3. **"The compiler must be verified as a once-proved theorem" for the hard passes.** The goal statement itself says "verified compiler, *and/or a validated translation at the bottom*," and thesis 3 makes per-run translation validation the cheapest proof there is. Pass 3 (regalloc) is already planned as validation; the same move is available for pass 2 (control-flow lowering, the named highest-risk item) — an untrusted lowering plus a verified per-run CFG-correspondence checker would reach bytes without ever closing the hardest simulation proof.

4. **"Arbitrary programs must be compilable" — i.e., spilling support.** LOWIR-DESIGN's own bootstrap shortcut notes that assuming ≤31 live registers removes pass 3 entirely, and thesis 1 says programs are *co-designed* with their proofs. Since you control every source program, `wf` can just reject >31-live-register functions forever, promoting the "shortcut" to the design. Spilling is an assumption inherited from general-purpose compilers, not from the goal.

5. **Rich non-local control (`block`/`brkB`/`contL`) in the proof-surface IL.** D3 bought flat error cascades at the functional-proof level and admits the cost "reappears" in pass 2. If the future borrow-checked HIR lowers early exits itself (it must have its own control constructs anyway), the verified fragment of Prog can stay structured-only and pass 2 collapses to near-trivial — again already sketched as the "restricted fragment" but treated as temporary rather than as the answer.

6. **"The borrow checker needs a proved soundness theorem before it's useful."** Ext. 5's level (c) (RustBelt-style soundness, "a large effort") is not on the critical path at all: the checker only ever *emits* `Wf`/`Disjoint` hypotheses that theorems take as preconditions. An unsound checker yields theorems with unsatisfiable preconditions — caught at composition, not silently trusted. An untrusted checker (rustc's own architecture, per thesis 1) fills the empty cell; verify it later, if ever.

7. **The prophecy translation (step 2 of the composition).** Creusot-style `{current, final}` encoding earns its keep at scale, but for a bootstrap libc the existing pattern — borrow gate produces spatial `Wf` facts, functions proved directly against functional specs at the IL — already works (hex0, strlen, strtoull). First-order-VCs-via-prophecies can be dropped from the success criteria and added as an ergonomics layer later.

8. **The GNU assembler/linker trust (TCB item 4) and hand-written `.s`.** `compileProgT`/`progBytes` already emit bytes directly. Once the shell and cores are Prog programs, `riscv64-linux-gnu-as`/`ld` leave the TCB entirely — this assumption is already deletable, it just hasn't been declared dead.

9. **"The I/O shell stays unproven" (TCB item 2).** That was a deliberate economy when the shell was hand-written asm below the proof line. With D7/D8 + the B1 entry-stub plan, the shell is expressible as a Prog function plus one verified prologue stub, and `compile_sim` transports its proof for free. The assumption is a relic of the pre-compiler era.

10. **The 16-encoding freeze (no `auipc`, no `bltu`, jal-pc-read tricks).** Ext. 12 rejects `auipc` because each new encoding was a new hand-trusted surface. But `decode_agrees`/`step_agrees` against riscv-coq is now a mechanical, per-form cross-check — the marginal cost of an encoding dropped from "new trust" to "one more proved case." Keeping the freeze buys position-independence arguments but is no longer load-bearing for trust; relaxing it simplifies codegen (e.g. `cref` becomes one `auipc`).

(One more for consistency rather than leverage: LIBC-FORMALIZE §4's recommendation of a **block+offset memory model** for the MiniC track is already contradicted by D5's flat-memory-plus-borrows decision — the corpus should drop it explicitly.)

## If the project succeeds — surprising solutions

1. **The "language" is never a standalone language — it's Lean.** ProgLib already writes programs as Lean terms; the SSA experiment is a Lean IR; the borrow checker would be a decidable Lean function. Success could look like an EDSL where the elaborator *is* the frontend, the checker *is* a `#guard`, and the empty cell is filled without ever writing a parser — surprising to anyone expecting a rustc-shaped artifact.

2. **No memory injection anywhere in a verified compiler for pointer programs.** The P1 frame-padding oracle makes IL and machine addresses *numerically equal* by ∀-quantifying a padding parameter, so the simulation relation is plain equality. If that pattern (already used for `sp₀`, `dbase`, `pad`) scales through calls and the borrow layer, the stack ships with zero CompCert-style injections or provenance — a result folk wisdom says is impossible on untyped flat words.

3. **The proofs are closed by machines, and the deliverable is the harness.** REPRO-FINDINGS isolates the wall precisely: models comprehend and *plan* the refinement but fail at raw proof-engineering execution under kernel elaboration. A success mode where the seL4-style "poor-man's `crunch`" (thesis 10) plus the elaboration-cost gotcha library turns loop-simulation lemmas into something mid-tier models close routinely — making the *methodology* the reproducible artifact, not the theorems.

4. **The trusting-trust loop actually closes.** The verified compiler's output bytes are delivered as hex0/hex1 source, assembled by the proven 724-byte seed on bare metal — the tower becomes a cycle where the thing that verifies the toolchain is itself the first rung of the toolchain. B6's "separate-runs" assumption is the one meta-level hinge, and it's already named.

5. **The borrow checker's natural home turns out to be the SSA IR, and out-of-SSA is trivial.** The experiment's assessment already hints at it: borrow signatures attach cleanly to single-assignment names, and with unbounded registers the classic lost-copy/swap hazards of SSA elimination *dissolve*. The textbook-hard parts of both borrows and SSA cancel each other — a composition surprise.

6. **UB doesn't exist, and neither do runtime checks.** N5 makes "going wrong" inexpressible at the IL by construction (total `exec`, total `mem`); the checker discharges everything above. A C-power systems stack with literally no UB, no sanitizers, and no dynamic checks — where safety is a *theorem precondition inventory* rather than a runtime property — would be the headline surprising outcome.

7. **The proofs never find a bug.** RESUME-PROGSIM already says it: "the theorem will not be defending a false claim — every lemma has an executable oracle." Success where differential testing + QEMU catch 100% of defects *before* proving, and the proofs function purely as certification/compression of tested truth, would upend the standard motivation story for verification — the oracle is the development tool, the theorem is the receipt.

8. **Recursion, termination, and stack safety all fall out of one fuel parameter.** C5 (the recursion policy) closes itself: fuel induction handles recursion for free, `∃ fuel` *is* the termination statement, and P1 folds the machine's stack overhead into the IL's own overflow check so the "stack budget hypothesis disappears." Three classically separate analyses collapse into one clock — no termination checker is ever built.

9. **One flat `mem : Word → Byte` from surface to silicon.** CompCert maintains a memory-model tower; here the same total flat function survives every altitude, with separation living entirely in contracts (D5, §5's one-liner). If that holds through the borrow-typed HIRs, the surprising lesson is that memory *models* were never necessary — only memory *disciplines*.

10. **The empty cell gets filled with almost no new research.** The composition in thesis 6 is four known components — rustc's checker kernel (small, sans closures/HRTBs), RustHorn/Creusot prophecies, a bedrock2/Pancake-class backend (this repo's `compile_sim`), and boundary borrows — each with a verified or shipped precedent. Success by *pure composition engineering*, where the only genuinely novel artifact is the glue (BorrowSig as the lingua franca between checker, specs, and compiler), would surprise the field precisely because everyone assumed the cell was empty for a research reason.

A cross-cutting observation: several "droppable assumptions" (1, 3, 4, 5) are already present in the docs as *shortcuts* or *fallbacks* — the corpus consistently treats the general case as the goal and the restricted case as a temporary economy. Inverting that stance — the restricted, co-designed case *is* the product, per thesis 1 — is probably the single highest-leverage reframe available.
